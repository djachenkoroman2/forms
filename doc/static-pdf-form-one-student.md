# Статичная PDF-форма на одного студента: рекомендация

Дата: 07.10.2026. Источник вопроса: [prompts/0003.txt](../prompts/0003.txt).

**Реализация:** форма `prepod_vnok_info` версии 2.0 — [описание, результаты проверки и матрица приёмки](../forms/prepod_vnok_info/docs/static-form.md). Пилотный образец проверен в Firefox 157 (заполнение, сохранение, повторное открытие и редактирование); остальные среды ещё не проверены.

## Вопрос

Можно ли сделать PDF-форму без интерактивных сценариев и кнопок, рассчитанную на одного студента (курсанта), так, чтобы её можно было сохранить и затем снова редактировать поля, с максимальной совместимостью с программами просмотра и браузерами?

## Короткий ответ

**Да. Для максимальной совместимости это лучший вариант.** Нужна обычная PDF-форма AcroForm с фиксированным набором полей: без XFA, без JavaScript и без кнопок. Такие поля заполняют и сохраняют Adobe Acrobat Reader, встроенные просмотрщики Chrome, Edge и Firefox, «Просмотр» на macOS и iPhone, Google Диск на Android. Сохранённый файл снова открывается для редактирования, а значения полей можно извлечь программно, без OCR.

Цена совместимости:

1. **Один файл — один студент.** Несколько студентов — несколько копий формы.
2. **Фиксированное число строк** расписания и достижений. Без сценариев строки нельзя добавлять и удалять во время заполнения.
3. **Нет проверок при вводе.** Обязательность полей и формат email проверяются при обработке файла, а не в форме.
4. **Многострочные поля имеют фиксированный размер.** Текст длиннее поля сохраняется полностью и извлекается, но на экране прокручивается, а на печать попадает только видимая часть.

Если эти ограничения допустимы, форму рекомендуется делать так. Если обязательны динамическое добавление записей и несколько студентов в одном файле, остаётся XFA с привязкой к Acrobat/Reader, как в [prepod_vnok_info](../forms/prepod_vnok_info/docs/viewer-setup.md), или веб-форма.

## Сравнение подходов

| Критерий | Статичная AcroForm (рекомендуется) | Динамическая XFA (prepod_vnok_info) |
| --- | --- | --- |
| Студентов в файле | 1 | Любое число |
| Строки расписания/портфолио | Фиксированное число | Добавляются кнопками |
| Acrobat Reader / Acrobat | Да | Да |
| Chrome, Edge, Firefox (встроенные просмотрщики) | Да (по документации) | Нет / только Edge с политикой администратора |
| «Просмотр» macOS, iPhone/iPad, Android | Да (по документации) | Нет |
| Проверка полей при вводе | Нет | Да |
| Программное извлечение | Простое: значения полей AcroForm | Отдельный разбор XML `datasets` |
| Поддержка технологии | Часть стандарта ISO 32000 | Устаревшая, вне стандарта ISO; Microsoft рекомендует отказ от неё |

## Совместимость по документации

Все строки ниже основаны на документации производителей. Для формы этого проекта фактически проверен только Firefox 157 ([результаты](../forms/prepod_vnok_info/docs/static-form.md#проверка-в-firefox)); остальные строки нужно подтвердить по [порядку проверки](#как-проверить-пилотный-образец).

| Среда | Заполнение и сохранение | Источник |
| --- | --- | --- |
| Adobe Acrobat Reader / Acrobat (Windows, macOS) | «Файл → Сохранить» | Эталонная реализация AcroForm |
| Google Chrome, настольный | Заполнение во встроенном просмотрщике. Сохранение: «Скачать» → **«С изменениями»** | [Справка Chrome](https://support.google.com/chrome/answer/16215622?hl=en&co=GENIE.Platform%3DDesktop) |
| Microsoft Edge, настольный | Встроенный просмотрщик заполняет AcroForm. Требует проверки | — |
| Mozilla Firefox 84+ | Заполнение AcroForm с версии 84. Поддерживаются сохранение и печать введённых значений | [Mozilla](https://blog.mozilla.org/attack-and-defense/2021/10/14/implementing-form-filling-and-accessibility-in-the-firefox-pdf-viewer/) |
| «Просмотр» (Preview), macOS | Заполнение полей. После сохранения можно открыть и продолжить заполнение | [Apple](https://support.apple.com/guide/preview/fill-out-and-sign-pdf-forms-prvw35725/mac) |
| iPhone / iPad | Приложение «Просмотр» или «Файлы» → кнопка заполнения формы → «Сохранить» | [Apple](https://support.apple.com/guide/iphone/fill-out-and-sign-pdf-forms-iphd7e3c0c74/ios) |
| Android | Google Диск: «Изменить» → «Заполнение формы» → «Сохранить» | [Google Drive](https://support.google.com/drive/answer/9463834?hl=en&co=GENIE.Platform%3DAndroid) |
| Safari (в браузере), онлайн-конвертеры, мессенджеры | Не рекомендуются: возможности заполнения и сохранения не подтверждены | — |

**Чего нельзя делать при сохранении:** «Печать → Сохранить как PDF» превращает форму в нередактируемую картинку без значений полей. Об этом нужно прямо сказать в инструкции для заполняющих.

## Технические требования к PDF

Совместимость определяют не только тип формы, но и детали изготовления. Обязательные правила:

1. **Только AcroForm.** В файле не должно быть `/XFA`, `/NeedsRendering`, JavaScript (`/JS`, `/AA`, `/OpenAction` со сценарием), кнопок и действий отправки. Допустимое исключение, принятое для `prepod_vnok_info` (draft03): стандартные действия формата поля даты `AFDate_KeystrokeEx`/`AFDate_FormatEx`. Программы без скриптов их игнорируют, а Acrobat и Firefox показывают календарь. Firefox при этом сохраняет дату в формате ГГГГ-ММ-ДД ([подробнее](../forms/prepod_vnok_info/docs/static-form.md#поле-даты)).
2. **Простые типы полей:** однострочные и многострочные текстовые поля, флажки. Редактируемые раскрывающиеся списки, поля даты с маской и форматирование чисел реализуются сценариями, поэтому их не использовать. Статус задания, время и дни недели — обычный текст или флажки.
3. **Кириллица.** В `/AcroForm /DR` встроить **полный** TrueType-шрифт с кириллицей, а не подмножество: просмотрщики перерисовывают поля шрифтом из `/DR`, и в подмножестве может не оказаться введённых букв. В `/DA` каждого поля указать этот шрифт и фиксированный размер, например 10 pt. Автоматический размер (`0`) в некоторых программах даёт нечитаемо мелкий текст.
4. **Внешний вид полей.** У каждого поля должен быть поток внешнего вида `/AP`, в том числе у пустых и у флажков в обоих состояниях. Не полагаться на `/NeedAppearances`: в PDF 2.0 этот флаг устарел, а часть программ его игнорирует.
5. **Без расширенных прав Reader** (Reader Extensions, подпись `UR3`). Современному Reader они для сохранения не нужны. При изменении файла в другой программе такая подпись нарушается, и Acrobat выдаёт предупреждения.
6. **Без защиты паролем и ограничений** на заполнение и изменение.
7. **Порядок Tab:** `/Tabs /R` (по строкам) на страницах и порядок создания полей сверху вниз. Значение `/S` требует структуры тегированного PDF; без неё оно не определено.
8. **Обязательные поля** пометить звёздочкой в подписи и флагом `Required`. Флаг учитывают не все программы, поэтому окончательная проверка выполняется при обработке.
9. **Версия PDF 1.7**, шрифт встроен, без внешних ресурсов.

## Поля формы на одного студента

Машинные имена — стабильные, иерархические, латиницей. Значения хранятся как текст: сохраняются `+`, ведущие нули и буквы.

| Имя поля | Подпись | Тип |
| --- | --- | --- |
| `meta.schema_version` | — (только чтение, значение `1.0`) | Текст, только чтение |
| `meta.form_id` | — (только чтение) | Текст, только чтение |
| `teacher.full_name` | ФИО преподавателя | Текст |
| `teacher.position` | Должность | Текст |
| `student.full_name` | Полные ФИО * | Текст |
| `student.group_code` | Шифр группы * | Текст |
| `student.phone` | Телефон * | Текст |
| `student.email` | Электронная почта * | Текст |
| `student.task` | Задача, поставленная преподавателем * | Многострочный текст |
| `schedule.N.mode` | Режим работы | Текст |
| `schedule.N.monday` … `schedule.N.sunday` | Пн … Вс | Флажки |
| `schedule.N.time_from`, `schedule.N.time_to` | Начало, окончание (ЧЧ:ММ) | Текст |
| `schedule.N.room` | Аудитория | Текст |
| `student.expected_results` | Ожидаемые результаты | Многострочный текст |
| `student.status` | Текущий статус выполнения задания | Текст |
| `achievements.N.text` | Достижение | Текст |
| `student.notes` | Примечание | Многострочный текст |

`N` — номер строки, например `schedule.1` … `schedule.5`, `achievements.1` … `achievements.10`. Число строк нужно согласовать заранее: в этом варианте оно является жёстким пределом. Для записей сверх предела можно добавить многострочное поле «Дополнительно» и описать его в инструкции. Номер строки описывает только позицию: пустые строки при извлечении пропускаются.

Идентификатор студента без сценариев внутри формы не создаётся. Идентификатор при необходимости назначает обработчик при приёме файла (например, по хешу или UUID) либо ответственный вписывает его заранее в поле только для чтения перед рассылкой.

Многострочные поля стоит делать крупными (задача — от трети страницы) и размещать на отдельной странице, чтобы видимая и печатаемая часть вмещала обычный объём текста.

## Извлечение данных

Значения читаются стандартными средствами, например `PdfReader(path).get_fields()` в pypdf, и раскладываются по именам полей в JSON той же структуры, что и у `prepod_vnok_info`: `schema_version`, `teacher`, `students` (один элемент), `schedule[]`, `achievements[]`. На этом этапе выполняются проверки, которых нет в форме: обязательные поля, формат email и времени. Несколько файлов одного преподавателя объединяются при обработке.

## Как проверить пилотный образец

До выпуска формы изготовить пилотный PDF и в каждой целевой среде выполнить:

1. Открыть пустую форму. Проверить кириллицу в подписях и полях, порядок Tab.
2. Заполнить все поля, включая длинный многострочный текст, `+00 001`, `001-А` и флажки дней.
3. Сохранить способом из таблицы совместимости, закрыть, открыть снова: значения на месте и редактируются.
4. Изменить и очистить часть полей, сохранить повторно.
5. Открыть файл, сохранённый в одной программе, в другой. Например: заполнить в Chrome, дозаполнить в «Просмотре», открыть в Acrobat Reader.
6. Извлечь данные скриптом и сверить с экраном.
7. Напечатать: проверить кириллицу и видимость текста в многострочных полях.

Минимальная матрица: Acrobat Reader (Windows), Chrome, Edge, Firefox, «Просмотр» macOS, iPhone, Android (Google Диск). В доступной среде разработки (Linux) можно проверить только Firefox. Остальные проверки выполняют пользователи на своих устройствах. Результаты записываются в документацию формы.

## Рекомендация

- Если допустимо «один файл — один студент» и фиксированное число строк расписания и портфолио, делать **статичную AcroForm** по требованиям выше. Это единственный вариант PDF, рассчитанный на работу в браузерах и на мобильных устройствах без настройки.
- Число строк расписания и достижений согласовать до изготовления, например 5 и 10.
- Начать с пилотного образца и проверки по матрице. Совместимость с конкретной программой заявлять только после её фактической проверки.
