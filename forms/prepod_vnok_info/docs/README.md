# Научная работа преподавателя со студентами

Идентификатор: `prepod_vnok_info`. Одна анкета описывает преподавателя, его студентов (курсантов), задачи, расписания и достижения.

**Статус: черновик; утверждённой версии нет.** Целевые просмотрщики — Adobe Acrobat Reader / Acrobat (Windows, macOS) и Microsoft Edge с настройкой администратора ([решение](../prompts/0003-acrobat-edge-v1.txt)). Фактическая проверка в них ещё не проводилась: в среде разработки (Linux) этих программ нет. Не выдавать форму преподавателям до прохождения [чек-листа приёмки](acceptance-checklist.md).

## Реализация и просмотрщик

PDF 1.7 содержит динамическую XFA-форму (шаблон 3.3), JavaScript и XML-пакет `datasets`. Это не AcroForm с фиксированным количеством карточек. Список студентов, расписания и портфолио описаны повторяемыми подформами с `max="-1"`; программного ограничения количества записей нет, практический предел зависит от памяти и просмотрщика и пока не измерен.

Нужен просмотрщик, который выполняет JavaScript XFA, управляет экземплярами подформ, пересчитывает страницы и сохраняет актуальные данные XFA в PDF:

| Среда | Статус |
| --- | --- |
| Adobe Acrobat Reader / Acrobat, Windows и macOS | Основная. Поддержка XFA подтверждена документацией Adobe; форма не проверена |
| Edge, режим IE с модулем Acrobat (Windows, Edge ≥ 132) | Предпочтительный вариант для Edge; нужен установленный Acrobat Reader и политика администратора. Не проверено |
| Edge, встроенный просмотрщик с политикой `PDFXFAEnabled` (Windows, macOS, Edge ≥ 104) | Экспериментальный; поддержка XFA ограничена. Не проверено |
| Firefox, Chrome, Safari, мобильные и прочие просмотрщики | Не поддерживаются. Firefox 157 проверен: добавление карточек не работает |

Подробности и пошаговая настройка — в [viewer-setup.md](viewer-setup.md).

В форме есть строка состояния под заголовком. Если сценарии выполняются, она становится зелёной и показывает программу и её версию. Иначе остаётся красной. В просмотрщике без XFA вместо формы отображается одна резервная страница с указанием, чем открыть файл. Число страниц, указанное `pdfinfo`, относится к этой странице; интерактивные страницы рассчитывает XFA-движок.

## Поля

Пути ниже относятся к экспортированному JSON. Звёздочкой помечены только обязательные для завершения поля; незавершённые черновики могут содержать пустые строки.

| Путь | Подпись / назначение | Тип | Обязательность для завершения |
| --- | --- | --- | --- |
| `teacher.full_name` | ФИО преподавателя | Текст | Нет |
| `teacher.position` | Должность | Текст | Нет |
| `students[].id` | Устойчивый служебный идентификатор | Текст, автоматически | Не поле ввода |
| `students[].full_name` | Полные ФИО * | Текст | Да |
| `students[].group_code` | Шифр группы * | Текст | Да |
| `students[].phone` | Телефон * | Текст | Да |
| `students[].email` | Электронная почта * | Текст | Да, базовая проверка email |
| `students[].task` | Задача преподавателя * | Многострочный текст | Да |
| `students[].schedule[]` | Записи расписания | Список | Нет |
| `schedule[].id` | Идентификатор занятия | Текст, автоматически | Не поле ввода |
| `schedule[].mode` | Режим работы | Свободный текст | Нет |
| `schedule[].weekdays` | Дни недели | Список отмеченных дней | Нет |
| `schedule[].time_from`, `time_to` | Начало и окончание | Текст `ЧЧ:ММ` или пустая строка | Нет |
| `schedule[].room` | Аудитория / место работы | Текст | Нет |
| `students[].expected_results` | Ожидаемые результаты | Многострочный текст | Нет |
| `students[].status` | Текущий статус задания | Свободный текст | Нет |
| `students[].achievements[]` | Портфолио | Список | Нет |
| `achievements[].id` | Идентификатор достижения | Текст, автоматически | Не поле ввода |
| `achievements[].text` | Достижение | Многострочный текст | Нет |
| `students[].notes` | Примечание | Многострочный текст | Нет |

`schedule[]` и `achievements[]` в сокращённых путях таблицы находятся внутри соответствующего `students[]`. Телефон и шифр группы не преобразуются в числа: сохраняются `+`, ведущие нули, буквы и разделители. Национальная маска телефона не навязывается. Статус допускает любой текст.

## Заполнение и сохранение

Пошаговая инструкция для преподавателя — [teacher-guide.md](teacher-guide.md). Кратко:

1. Открыть копию PDF в Acrobat Reader. Строка состояния должна быть зелёной. Появляются пустые поля преподавателя и одна пустая карточка студента.
2. «Добавить студента (курсанта)», «Добавить занятие», «Добавить достижение» создают записи; кнопки «Удалить…» удаляют запись после подтверждения. Ответ «Нет» сохраняет запись.
3. «Проверить заполнение» проверяет пять обязательных полей каждого студента, формат email и времени `ЧЧ:ММ`. Проверка не запускается при сохранении, поэтому незавершённую форму можно записать.
4. Сохранять командой «Сохранить» / «Сохранить как…». «Печать в PDF» удаляет интерактивность и данные XFA.

## Известные ограничения

- Форма работает только в средах из таблицы выше. В обычных браузерах и на мобильных устройствах кнопки не работают.
- Ни одна целевая среда ещё не проверена фактически. Сохранение без расширенных прав Reader (Reader Extensions) также подлежит проверке.
- Многострочные поля не ограничены по длине; текст полностью сохраняется в данных. Поле растёт, карточкам разрешён перенос на следующую страницу (`keep intact="none"`). Перенос **одного** поля с текстом длиннее страницы, печать такого текста и порядок Tab нужно проверить в Acrobat (пп. 7, 8, 12 чек-листа). Если перенос не работает, текст, не уместившийся на странице, останется в данных и будет извлечён, но не будет виден при печати.
- Удаление записи после подтверждения нельзя отменить внутри формы; восстановление — из последней сохранённой копии.
- Microsoft называет XFA устаревшей технологией. Поддержка в Edge может измениться в будущих версиях.

## Сборка и проверки

Команды выполняются из `forms/prepod_vnok_info/`. Нужны Python 3.12+, шрифт DejaVu Sans и Node.js для проверки JavaScript.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r src/requirements.txt
.venv/bin/python src/build_form.py
.venv/bin/python -m unittest discover -s src -p 'test_*.py' -v
node src/test_form_logic.cjs
```

Сборщик выбирает следующий свободный номер в `output/drafts/`, не перезаписывая выпущенные файлы. Можно указать `--output /путь/новый.pdf` и `--font /путь/DejaVuSans.ttf`. По умолчанию шрифт берётся из `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf`. В другие ОС Python-зависимости и шрифт устанавливаются отдельно. Исходный UUID первой карточки создаётся при каждой сборке, поэтому новый файл не обязан побайтно совпадать с предыдущим.

В ходе проверки 07.10.2026 зависимости были установлены в `/tmp/forms-venv`; это временное окружение, оно не входит в проект. Устанавливать Node.js для заполнения PDF не требуется.

## Машинное извлечение данных

```bash
.venv/bin/python src/extract_data.py output/drafts/prepod_vnok_info-v1.0-draft04.pdf
.venv/bin/python src/extract_data.py /путь/заполненный.pdf --output /путь/новый.json
```

Без `--output` JSON выводится в stdout. Существующий JSON не перезаписывается. Поддерживаются `/AcroForm/XFA` в виде массива пакетов и единого XDP-потока. Парсер читает `datasets` из актуальной ревизии PDF; изображения и визуальное расположение полей не анализируются. Несовместимая форма, неизвестная версия схемы, пустые/повторяющиеся идентификаторы и небезопасный XML приводят к понятной ошибке.

Корень данных содержит `schema_version: "1.0"`, `form_id: "prepod_vnok_info"`, `teacher` и `students`. В XML записи находятся в `formData/students/student`, занятия — в `schedule/entry`, достижения — в `achievements/achievement`. Эти связи преобразуются во вложенные массивы JSON. Порядок массива отражает порядок записей, идентификатор от позиции не зависит. Пустые текстовые значения представлены как `""`, пустые списки — как `[]`; `null` не используется. Дни недели кодируются `monday` … `sunday`.

Данные полей связаны с `datasets` через стандартное сопоставление имён XFA. Отдельной копии JSON внутри PDF нет. Синхронизацию при заполнении и сохранении выполняет просмотрщик; сквозная проверка этой синхронизации остаётся обязательной. `get_fields()` для AcroForm здесь не заменяет чтение XFA.

JSON Schema описывает в том числе незавершённые черновики: `required` означает наличие ключа, а не непустой ответ. Метка `x-requiredForCompletion` документирует обязательность для завершения; обычный валидатор JSON Schema эту пользовательскую метку не исполняет. Извлечение не является проверкой готовности анкеты и сохраняет введённый текст без исправления.
