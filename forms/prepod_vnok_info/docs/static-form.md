## Чем отличается от версии 1.0

| | v1.0 (XFA) | v2.0 (эта) |
| --- | --- | --- |
| Технология | Динамическая XFA, JavaScript, кнопки | AcroForm без XFA и кнопок; JavaScript — только стандартный формат поля даты |
| Студентов в файле | Любое число | Один. На каждого студента — отдельная копия |
| Расписание | Записи добавляются кнопками | Одно поле со свободным текстом |
| Портфолио | Записи добавляются кнопками | 10 строк |
| Проверка заполнения | Кнопка в форме | При обработке: `extract_static.py --check` |
| Просмотрщики | Acrobat/Reader; Edge после настройки | Acrobat/Reader, браузеры, «Просмотр», мобильные (см. ниже) |
| JSON | [Схема 1.0](data-schema.json) | [Схема 2.0](data-schema-v2.json) |

## Состав формы

Три страницы A4. Поля, отмеченные `*`, обязательны и помечены флагом `Required`. Значения нигде не преобразуются: сохраняются `+`, ведущие нули, буквы и разделители.

| Поле PDF | Метка | Тип | Путь в JSON (схема 2.0) |
| --- | --- | --- | --- |
| `meta.date_filled` | Дата заполнения (ДД.ММ.ГГГГ) | Поле даты `dd.mm.yyyy` ([подробнее](#поле-даты)) | `date_filled` |
| `teacher.full_name` | ФИО преподавателя | Текст | `teacher.full_name` |
| `teacher.position` | Должность | Текст | `teacher.position` |
| `teacher.department` | Кафедра | Текст | `teacher.department` |
| `student.last_name` | Фамилия * | Текст | `students[0].last_name` |
| `student.first_name` | Имя * | Текст | `students[0].first_name` |
| `student.middle_name` | Отчество | Текст | `students[0].middle_name` |
| `student.course` | Курс | Текст | `students[0].course` |
| `student.group_code` | Шифр группы * | Текст | `students[0].group_code` |
| `student.phone` | Телефон * | Текст | `students[0].phone` |
| `student.email` | Электронная почта * | Текст | `students[0].email` |
| `student.status` | Текущий статус выполнения задания | Текст | `students[0].status` |
| `student.schedule` | Расписание работы с преподавателем | Многострочное, не менее 8 строк | `students[0].schedule` (строка) |
| `student.task` | Задача, поставленная преподавателем * | Многострочное, около 30 строк | `students[0].task` |
| `student.expected_results` | Ожидаемые результаты | Многострочное | `students[0].expected_results` |
| `achievements.N.text` | Достижение N | Многострочное, 2 строки | `students[0].achievements[]` |
| `student.notes` | Примечание | Многострочное | `students[0].notes` |
| `meta.form_id`, `meta.schema_version` | — (скрытое служебное поле) | Скрытое, только чтение | `form_id`, `schema_version` |
| `student.id` | — (скрытое служебное поле) | Скрытое, только чтение | `students[0].id` |

В форме 26 видимых полей. Три служебных поля **не показываются в форме и не печатаются**: флаг аннотации `Hidden`, без `Print`; Tab их пропускает. Они нужны только для обработки: по ним извлечение узнаёт форму и версию схемы, а `prepare_copy.py` записывает ID анкеты.

`N` = 1…10 (константа `ACHIEVEMENT_ROWS` в [build_static_form.py](../src/static/build_static_form.py); её изменение означает новую версию формы). Если строк портфолио не хватает, заполняющего просят дописать остальное в «Примечание».

## Поле даты

`meta.date_filled` оформлено как стандартное поле даты PDF-форм: Acrobat создаёт такое же, если выбрать категорию формата «Дата». У поля два действия:

- `/AA /K` — `AFDate_KeystrokeEx("dd.mm.yyyy");`;
- `/AA /F` — `AFDate_FormatEx("dd.mm.yyyy");`.

Это **единственный JavaScript в форме**. Других сценариев, действий открытия документа, кнопок и отправки нет; тест это проверяет. Функции `AFDate_*` встроены в просмотрщики, которые выполняют скрипты PDF-форм, сам код в PDF не передаётся.

| Среда | Поведение |
| --- | --- |
| **Firefox 157 (PDF.js 6.3)** — проверено | При фокусе поле превращается в системный выбор даты с календарём. В русской локали дата показывается и вводится как `07.10.2026`. **В файл записывается `2026-10-07` (ISO)** — и как значение, и как внешний вид поля. После повторного открытия Firefox показывает `2026-10-07`, пока поле не выделено |
| Adobe Acrobat / Reader | По [документации Adobe](https://helpx.adobe.com/acrobat/kb/support-for-image-and-date-fields-in-acroforms.html) (с выпуска января 2017 года): у текстового поля с форматом «Дата» при фокусе появляется значок календаря; выбранная дата вводится в заданном формате. Отклонение неверной даты и отображение `ДД.ММ.ГГГГ` — штатное поведение `AFDate_*`. Не проверено |
| Chrome, Edge (PDFium) | Скрипты формата частично поддерживаются; календаря, вероятно, нет. Не проверено |
| «Просмотр» macOS, iPhone/iPad, Android, программы с отключённым JavaScript | Скрипты не выполняются, поле остаётся обычным текстовым: дату вводят вручную. По документации; не проверено |

Как обрабатываются разные варианты при извлечении:

- `extract_static.py` приводит корректную ISO-дату `ГГГГ-ММ-ДД`, которую записывает Firefox, к `ДД.ММ.ГГГГ`. В JSON дата всегда в формате схемы 2.0. Другие значения не изменяются.
- `--check` по-прежнему проверяет формат и существование даты: в программах без скриптов дату можно ввести как угодно.
- **Главный риск для приёмки:** как Acrobat покажет дату `2026-10-07`, сохранённую Firefox. Формат `AFDate_FormatEx` может не распознать ISO-дату и показать поле пустым, хотя значение в файле сохранится. Это отдельный пункт матрицы приёмки.
- Альтернатива, если риск подтвердится или единообразие важнее привычного вида: формат `yyyy-mm-dd` (метка «ГГГГ-ММ-ДД»). Тогда Firefox, Acrobat и программы без скриптов будут показывать и хранить дату одинаково.

## Раскладка

- Сетка: метка в левой колонке шириной 30% ширины содержимого (153 pt), поле в правой колонке шириной 70% (357 pt). Ширина одинакова для всех 26 видимых полей.
- Метки однострочных полей выровнены по вертикальному центру поля, многострочных — по первой строке поля.
- Длинные метки переносятся внутри левой колонки (отступ 8 pt до поля). Если метка выше поля, высота строки увеличивается.
- Заголовки разделов, вводная инструкция и пояснения занимают всю ширину. Заголовок раздела не отрывается от первой строки раздела: если строка не помещается, оба переносятся на новую страницу.
- Страницы:
  1. инструкция, дата, преподаватель, студент, расписание;
  2. задача и ожидаемые результаты;
  3. портфолио и примечание.
- Порядок Tab (`/Tabs /R`): дата, поля преподавателя, студента, расписание, задача, ожидаемые результаты, достижения 1–10, примечание. Поля только для чтения Tab пропускает. У каждого поля есть подсказка `/TU`, совпадающая с меткой, включая звёздочку.

## Шрифт

Times New Roman — проприетарный шрифт: его нельзя добавить в репозиторий и распространять вместе с исходниками. Поэтому используется **Liberation Serif** — шрифт с метриками Times New Roman и полной кириллицей, лицензия SIL Open Font License 1.1 ([текст лицензии](../src/static/fonts/OFL.txt)). Файлы шрифтов лежат в [src/static/fonts/](../src/static/fonts/).

- **Liberation Serif Regular** — для полей и обычного текста. Встраивается **полностью** (Type0/CIDFontType2, `Identity-H`, `/ToUnicode`) и подключён в `/AcroForm/DR` под именем `/Serif`. Поэтому просмотрщик может отрисовать любой введённый позже символ кириллицы. Размер текста в полях — 11 pt, в портфолио — 10 pt.
- **Liberation Serif Bold** — только для неизменяемых меток и заголовков. Встраивается подмножеством, с сохранением номеров глифов. Полям он не нужен.

Firefox (PDF.js) во время редактирования показывает текст поля своим системным шрифтом. После сохранения внешний вид поля строится шрифтом из формы: проверено растеризацией файла, сохранённого Firefox.

## Порядок рассылки и приёма

1. **Подготовить копию на каждого студента.** Пустой PDF не раздавайте напрямую: у него нет ID анкеты.

   ```bash
   .venv/bin/python src/static/prepare_copy.py output/drafts/prepod_vnok_info-v2.0-draft04.pdf \
       /путь/Иванов_студент1.pdf --teacher-name "Иванов И. И." --teacher-position "Доцент" \
       --teacher-department "Кафедра физики"
   ```

   Скрипт записывает в скрытое поле `student.id` уникальный `student-<UUID>`; заполняющий его не видит. Данные преподавателя заполняются при необходимости. Существующие файлы не перезаписываются. Повторная подготовка уже подготовленной копии запрещена, чтобы ID не повторялись.
2. Передать копию преподавателю вместе с [инструкцией](teacher-guide-static.md).
3. Принять заполненный PDF и извлечь данные с проверкой:

   ```bash
   .venv/bin/python src/static/extract_static.py /путь/заполненный.pdf --check --output /путь/результат.json
   ```

   **Ошибки** (код выхода `2`):
   - незаполненные обязательные поля: фамилия, имя, шифр группы, телефон, email, задача;
   - неверный формат email;
   - дата не в формате `ДД.ММ.ГГГГ` или несуществующая, например `31.02.2026`.

   **Предупреждение** (на код выхода не влияет): курс — не целое число от 1 до 6.

   Сообщения выводятся в stderr, JSON записывается в любом случае. Для файла без ID нужен флаг `--assign-id`: он выдаёт временный ID с предупреждением, сам PDF не изменяется.

## Извлечение данных и схема 2.0

[extract_static.py](../src/static/extract_static.py) читает значения полей AcroForm через pypdf, без OCR, и формирует JSON по [схеме 2.0](data-schema-v2.json). Пример: [example-data-v2.json](example-data-v2.json).

Для тестирования программ обработки есть [набор из 20 заполненных форм](../examples/README.md) на вымышленных данных одной кафедры. В наборе только PDF; ожидаемые данные, код выхода и сообщения `--check` описаны в README набора: 14 форм без ошибок (из них 2 с предупреждением о курсе), 5 форм с ошибками проверки и 1 форма без ID анкеты (ошибка извлечения). **Расхождение:** при дате вида `7.10.2026` извлечённый JSON не соответствует шаблону `date_filled` в схеме 2.0 ([подробнее](../examples/README.md#расхождение-пример-17-и-схема-20)).

- Корень: `schema_version` (`"2.0"`), `form_id`, `date_filled`, `teacher` {`full_name`, `position`, `department`}, `students` (ровно один элемент).
- Студент: `id`, `last_name`, `first_name`, `middle_name`, `course`, `group_code`, `phone`, `email`, `task`, `schedule` (строка), `expected_results`, `status`, `achievements[]` {`id`, `text`}, `notes`.
- Пустые строки портфолио пропускаются. `achievements[].id` = `achievement-N`, где `N` — номер строки в форме. Он не меняется, если очистить другие строки.
- Пустые необязательные поля — `""`, пустой список — `[]`, `null` не используется. Дата и курс сохраняются как введены, без преобразования.
- Переводы строк `\r` и `\r\n`, которые записывают некоторые программы, приводятся к `\n`.
- **Файлы draft01 (схема 1.0)** отклоняются с сообщением о том, что данные нужно перенести в форму draft02 или новее. Неполные данные не выдаются. Для XFA-версии 1.0 используется `src/extract_data.py`. Обычный PDF и другая форма дают понятную ошибку.

Схема 1.0 ([data-schema.json](data-schema.json), [пример](example-data.json)) осталась без изменений для XFA-версии.

### Проверка в Firefox (draft04)

Автоматизированный сценарий [firefox_check.py](../src/static/firefox_check.py) запускает Firefox в headless-режиме с временным профилем и управляет им через WebDriver BiDi. Заполнение идёт через интерфейс встроенного просмотрщика PDF.js. Фамилия «Ёлкина» и дата (цифры `07102026` в системном выборе даты) вводятся реальными нажатиями клавиш, остальные поля — через события полей ввода. Сохранение выполняется функцией самого PDF.js, той же, что вызывает кнопка «Сохранить». Затем сохранённый файл открывается заново.

Результаты для подготовленной копии `v2.0-draft04`:

1. Первый цикл ([значения](../src/static/firefox_values_example.json)): заполнены 17 полей, включая дату, кафедру, курс, три поля ФИО, многострочные расписание и задачу и два достижения. При фокусе поле даты стало системным выбором даты, ввод `07102026` дал `07.10.2026`. После сохранения и повторного открытия все поля показывают введённые значения; дата показана как `2026-10-07` (см. [поле даты](#поле-даты)).
2. Второй цикл на сохранённом файле ([изменения](../src/static/firefox_values_edit_example.json)): изменены статус, курс и расписание, очищены отчество и одно достижение, добавлено новое достижение. После сохранения и повторного открытия расхождений нет.
3. Извлечение из файлов обоих циклов совпадает с введёнными данными: `date_filled` = `07.10.2026` после нормализации. Очищенные значения отсутствуют, ID анкеты одинаковый, `--check` ошибок и предупреждений не выдаёт.
4. Внешний вид полей, созданный Firefox при сохранении, правильно отображается в poppler: Liberation Serif, кириллица корректна. Дата во внешнем виде — `2026-10-07`.
5. Порядок Tab соответствует описанному выше.
6. Скрытые служебные поля PDF.js создаёт как элементы нулевого размера с `visibility: hidden`, недоступные для ввода и фокуса. ID анкеты сохраняется после двух сохранений в Firefox; в тексте страниц служебных данных нет.

### Матрица приёмки

Для каждой среды:

1. Открыть подготовленную копию.
2. Заполнить все поля: кириллица, `+00 001`, `001-А`, дата (через календарь, если он есть, и вручную), курс, длинная задача и расписание. Записать, есть ли календарь у поля даты и отклоняется ли дата `31.02.2026`.
3. Сохранить способом из [инструкции](teacher-guide-static.md), закрыть, открыть снова, дозаполнить и снова сохранить.

## Сборка и тесты

Команды выполняются из `forms/prepod_vnok_info/`. Зависимости — в [requirements.txt](../src/requirements.txt). `websocket-client` нужен только для проверки в Firefox.

```bash
.venv/bin/python src/static/build_static_form.py            # следующий v2.0-draftNN в output/drafts/
.venv/bin/python -m unittest discover -s src/static -p 'test_*.py' -v
```

14 модульных тестов проверяют:

- отсутствие XFA, кнопок, действий документа и страниц, шифрования и прав Reader; JavaScript — только `AFDate_KeystrokeEx`/`AFDate_FormatEx("dd.mm.yyyy")` у поля даты;
- заголовок и число страниц;
- Liberation Serif: полное встраивание шрифта полей, подмножество Bold только для меток, `/ToUnicode`, `/AP` и `/DA` у каждого поля, `/Tabs /R`;
- сетку 30/70: координаты и ширину всех видимых полей, отсутствие наложений и выхода за поля страницы, отсутствие текста меток в колонке полей;
- скрытость служебных полей (флаг `Hidden` без `Print`), отсутствие служебного текста на страницах, 26 видимых полей;
- состав полей, обязательные поля, поля только для чтения и многострочные, высоту расписания не менее 8 строк, совпадение `/TU` с метками;
- путь «пример схемы 2.0 → заполнение → извлечение» без потерь;
- пустую форму: 6 ошибок обязательных полей; отчество, курс и дата не обязательны;
- даты: `31.02.2026`, `7.10.2026`, `2026-02-31` — ошибки; `2026-10-07` из Firefox приводится к `07.10.2026`; курс (`0`, `7`, `третий` — предупреждения), email;
- сохранение текста как есть: 1500 строк в задаче и расписании, `+00 001`, `001-А`, курс `03`;
- редактирование и очистку после сохранения, переводы строк `\r`;
- уникальность ID, защиту от перезаписи, отказ при draft01 (схема 1.0), XFA и обычном PDF.

Дополнительно пример и извлечённые данные пустой формы проверены валидатором JSON Schema (jsonschema, draft 2020-12) по [data-schema-v2.json](data-schema-v2.json). Эта проверка выполнена разово и не входит в зависимости проекта.

## Технические решения

- Только AcroForm и только текстовые поля. Нет `/XFA`, `/NeedsRendering`, кнопок, действий документа, шифрования и `UR3`. JavaScript — только стандартные действия формата у поля даты.
- У каждого поля есть внешний вид `/AP` с переносом строк. `/NeedAppearances` не используется.
- `prepare_copy.py` и тесты перерисовывают внешний вид полей той же функцией, что и сборщик, используя шрифт, встроенный в сам PDF.
- Высоты расписания, задачи и примечания рассчитываются от оставшегося места на странице. Минимальная высота расписания — 110 pt (константа `SCHEDULE_MIN_H`), это не менее 8 строк по 11 pt.

## Известные ограничения

- Один студент в файле, 10 строк портфолио. Добавлять записи в форме нельзя.
- Календарь у поля даты есть только в программах, выполняющих скрипты форм (Firefox — проверено; Acrobat — по документации). Firefox сохраняет дату в ISO-формате, см. [поле даты](#поле-даты). Других проверок в форме нет: обязательность и форматы проверяются при обработке (`--check`). PDF.js подсвечивает обязательные поля рамкой, другие программы могут их не выделять.
- Многострочные поля имеют фиксированный размер. Текст сверх видимой области сохраняется и извлекается полностью, но при печати выводится только видимая часть. Ориентиры: задача — около 30 строк, расписание — около 10 строк.
- В Liberation Serif нет иероглифов и редких символов: они отобразятся пустыми прямоугольниками, хотя в данных сохранятся.
- Данные, заполненные в draft01, не переносятся автоматически: изменились поля ФИО и расписания.
- Целевые программы, кроме Firefox, не проверены. Печать не проверялась ни в одной программе, кроме растеризации poppler.
- Исходники draft01 (Liberation Sans, схема 1.0) заменены исходниками draft02. Draft01 — промежуточный черновик, и правила проекта требуют хранить исходники только для утверждённых выпусков. Для воспроизведения draft01 исходники нужно зафиксировать в git до коммита этих изменений.
