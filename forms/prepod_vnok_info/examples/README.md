Примеры нужны для тестирования программ, которые обрабатывают эти формы. Требования: [0007.txt](../prompts/0007.txt) → [0007_improved.txt](../prompts/0007_improved.txt), [0008.txt](../prompts/0008.txt) → [0008_improved.txt](../prompts/0008_improved.txt).

**Все данные вымышлены.** ФИО придуманы. Почта только в доменах `example.org`, `example.com`, `example.ru`. Телефоны вида `+7 (900) 000-00-NN` — тестовые номера.

### Расхождение: пример 17 и схема 2.0

`extract_static.py` выводит дату так, как она введена (см. [docs/static-form.md](../docs/static-form.md#извлечение-данных-и-схема-20)). Поэтому JSON, извлечённый из примера 17, содержит `"date_filled": "7.10.2026"`. В [схеме 2.0](../docs/data-schema-v2.json) у `date_filled` задан шаблон `^(?:|\s*\d{2}\.\d{2}\.\d{4}\s*)$`, и валидатор JSON Schema такой JSON отклоняет. Данные, извлечённые из остальных 18 примеров, схеме соответствуют (проверено jsonschema, draft 2020-12, 08.10.2026). Любое значение даты, кроме пустой строки, `ДД.ММ.ГГГГ` и корректной ISO-даты, даёт JSON вне схемы, хотя `--check` при этом корректно сообщает об ошибке.

Решить, что исправлять, нужно отдельно: ослабить шаблон в схеме или выдавать ошибку вместо JSON. Программа обработки до этого решения должна учитывать, что такой JSON возможен.

### Чего в наборе нет

Эти случаи проверяют модульные тесты в [src/static/test_static_form.py](../src/static/test_static_form.py): извлечение с `--assign-id` (временный ID случаен, поэтому побайтного ожидания нет), файлы draft01 (схема 1.0), XFA-версия, обычный PDF без полей. Нет также двух файлов с одинаковым ID анкеты: `prepare_copy` такое не допускает.

## Проверка

Команды выполняются из `forms/prepod_vnok_info/`:

```bash
.venv/bin/python src/static/extract_static.py examples/09-bad-email-and-date.pdf --check
.venv/bin/python -m unittest discover -s examples -p 'test_*.py' -v
```

[test_examples.py](test_examples.py), 5 тестов:

- для каждого PDF запускает `extract_static.py --check` и сравнивает stdout, код выхода и строки stderr с ожиданиями из `CASES`. Ожидаемый JSON строится в памяти, файлов JSON в папке нет (это тоже проверяется);
- проверяет, что кафедра во всех примерах, кроме 02, равна `DEPARTMENT`;
- проверяет, что у одного преподавателя не меньше трёх студентов;
- проверяет, что значения полей в PDF соответствуют исходным данным генератора, включая сырые значения `/V`: ISO-дату в 06, `\r` и `\r\n` в 13, отсутствие ID в 20.

## Повторная генерация

Исходные данные всех случаев находятся в [generate_examples.py](generate_examples.py). Ожидаемые данные и сообщения `--check` задаются там вручную, а не вычисляются через `extract_static.py`. Поэтому набор проверяет обработку, а не повторяет её. Значения, которые в PDF записаны иначе, чем в JSON (ISO-дата, переводы строк `\r`), указаны в `pdf_values` случая.

```bash
.venv/bin/python examples/generate_examples.py --force
```

Без `--force` скрипт отказывается работать, если файлы набора уже есть. С `--force` удаляются и создаются заново только PDF из списка случаев. Повторная генерация из той же формы даёт побайтно те же PDF (проверено 08.10.2026 сравнением SHA-256). Если изменится форма или схема данных, набор нужно пересоздать от новой формы: путь к ней — константа `FORM` в генераторе.
